# v0.4.0 Portfolio Brief Design

**Status:** Approved for implementation on 2026-08-15.

## Goal

Make `brief` useful for both one repository and the entire registered portfolio while keeping the existing focused briefing behavior backward-compatible.

## Scope

The release contains two vertical slices:

1. A typed, bounded portfolio response contract with prompt and parser tests.
2. Dual-mode Cobra command behavior with one provider call for a zero-argument portfolio brief and the existing focused flow for one argument.

The release does not add persistence, a new provider, a new command, background work, or autonomous repository changes.

## Design

`internal/ai` owns the model-facing contract. It will add:

```go
type PortfolioBriefItem struct {
	RepoName     string   `json:"repo_name"`
	Summary      string   `json:"summary"`
	CurrentFocus string   `json:"current_focus"`
	Blockers     []string `json:"blockers"`
	NextSteps    []string `json:"next_steps"`
}

type PortfolioBriefResponse struct {
	Repos []PortfolioBriefItem `json:"repos"`
}

func BuildPortfolioBriefPrompt(repos []models.RepoData, goals models.GoalsData) string
func ParsePortfolioBriefResponse(raw string) (PortfolioBriefResponse, error)
```

The portfolio prompt will include each supplied repository once, with its branch, abbreviated HEAD, recent commits, diffs, plan summary, notes, and goals. Repository-derived text remains explicitly delimited untrusted data. The prompt requires JSON only with one response item per supplied repository.

The parser will strip the same optional JSON fences as existing responses and reject malformed JSON, a missing `repos` field, empty repository names, duplicate repository names, and overlong text/list values. Limits are enforced before rendering so a provider response cannot flood terminal output.

`cmd/brief.go` will change the public usage from `brief <partial-name>` to `brief [partial-name]` and accept at most one argument. With no argument, it will:

- reject an empty registry with `brief: no repositories registered; run: devpulse register <path>`;
- collect registered repositories in the manager's existing stable name order;
- call `ai.Run` exactly once with the portfolio prompt and parser; and
- render each returned repository in stable order without ANSI-dependent content.

With one argument, it will preserve the existing fuzzy matching, collection, cache, provider, parser, and focused rendering flow.

## Error and compatibility behavior

- Zero repositories fail before any provider call.
- Collection errors identify the repository that failed and stop the portfolio request.
- Ambiguous and invalid one-argument queries retain the existing candidate/error behavior.
- `BriefResponse`, `BuildBriefPrompt`, `ParseBriefResponse`, and `renderBrief` remain unchanged for focused mode.
- The command remains read-only with respect to registered repositories and repository files.

## Verification

- Parser tests cover valid JSON, fenced JSON, missing `repos`, empty names, duplicate names, oversized fields, and malformed JSON.
- Command tests cover zero arguments, one exact/partial argument, ambiguous and invalid arguments, no registered repositories, collection failure, stable output, and the one-call portfolio path.
- `go test ./internal/ai -run 'Portfolio|Brief' -v`, focused command tests, `go test ./...`, `go vet ./...`, and `go build ./...` must pass before the v0.4.0 merge.
