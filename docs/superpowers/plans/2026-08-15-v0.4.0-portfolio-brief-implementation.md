# v0.4.0 Portfolio Brief Implementation Plan

> **For agentic workers:** Implement this plan task-by-task with test-first development and a verification checkpoint after each task.

**Goal:** Add a safe portfolio brief mode while preserving focused single-repository brief behavior.

**Architecture:** Keep model contracts and prompt construction in `internal/ai`; keep Cobra argument resolution, repository collection, pipeline wiring, and terminal rendering in `cmd/brief.go`. Reuse the existing `config.Manager.ListRepositories`, collector options, cache, and `ai.Run` pipeline rather than creating a second command path or provider abstraction.

**Tech Stack:** Go 1.25.12, Cobra, existing `internal/ai` clients and pipeline, go-git-backed collector, standard-library JSON and testing.

## Global Constraints

- `brief` accepts zero or one repository argument; more than one argument is rejected by Cobra.
- Zero-argument brief collects every registered repository in the manager's existing name-sorted order and performs exactly one provider call.
- One-argument brief preserves the current focused flow and response contract.
- Repository-derived content is untrusted data and must stay inside the existing prompt data-block boundary rules.
- The CLI remains read-only and must not add persistence or provider dependencies.
- Every task ends with focused tests, `gofmt`, and a conventional commit.
